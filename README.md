# Kentish Lodge MCST — public site & estate records

Public documents and services for **Kentish Lodge, MCST Plan No. 2405** —
served by GitHub Pages at **info.kentishlodge.com**.

## What lives here

| Path | What |
|------|------|
| `_bylaws/` | The bylaws — **immutable, authoritative text**. Never edited editorially. |
| `_policies/` | Operating policies (how bylaws are applied). Iteratively improved; each carries owner, review date, records produced and version history. Upgrade template below. |
| `_announcements/`, `announcements/` | Notices; auto-expire via `ends_on`/`status` front matter. |
| `_forms/`, `forms/apply.html` | Official forms + the online fill/print/submit app (definitions in `FORMS` inside that file). |
| `tools/issues.html` | **Residents:** report issues, track them (ref + PIN), resident accounts, follow-ups. |
| `tools/visits.html` | **Office:** site visits & inspections, issue triage, corrective actions with evidence. Admin-key gated. |
| `tools/letters.html` | **Office:** draft, print and record official letters (warnings, 14-day compliance notices, admin charges, appeal records). Admin key for recording. |
| `assets/bylaws-index.js` | Auto-generated bylaw/rule index used by the letters tool. Regenerate: `node tools/gen-bylaw-index.mjs`. |
| `backend/` | PHP endpoints deployed on the VPS (not GitHub Pages): `form-submit.php` (form email) and `records-api.php` (SQLite records for issues/visits/letters/appeals/accounts). See `backend/readme.md`. |

## The records model

Every operational artefact gets a reference: issues **KL-IR**, site visits
**KL-SV**, letters **KL-LTR**, appeals **KL-AP**. Residents see their own
issue timelines (internal notes hidden); the office sees everything and can
link letters and visits to issues. All of it is stored in one SQLite database
behind `records-api.php` on the estate's VPS — nothing sensitive lives on
GitHub Pages.

## Policy upgrade template

Copy this skeleton when upgrading a policy (bylaws are immutable — policies
cite them, never restate them as policy):

```markdown
---
title: "[Policy name] Policy"
category: [CATEGORY]
effective: [YYYY-MM-DD]
version: 1.0
order: "[NN.NN]"
bylaws:
  - [bylaw-slug]
owner: [Who operates this policy]
review_by: [YYYY-MM-DD]
records:
  - "[What records this policy produces and where they live]"
---

## 1. Purpose        — one paragraph
## 2. Authority & scope — which bylaw rules this operationalises
## 3. Procedure      — numbered steps a competent stranger could follow
## 4. Service standards — measurable response/turnaround commitments
## 5. Records        — KL-IR / KL-SV / KL-LTR / KL-AP refs and what gets written down
## 6. Appeals        — standard 14-day written appeal clause + link to Appeals Policy
## 7. Version history — table: version / effective / change
```

## Development

- Jekyll (GitHub Pages builds automatically on push; `_config.yml` `exclude`s
  repo tooling from the published site).
- DOM smoke tests: `npm install` once, then `node tests/apply.dom.test.js`,
  `node tests/tools.dom.test.js`. CI runs them on every push.
- The three tools are dependency-free static pages sharing the site's civic
  editorial design system; API base URLs are constants at the top of each
  file (`?api=` query param overrides for testing).
